# Reproduce the SoundCraft go/no-go check

## Run the pinned probe

Prerequisites are this macOS Apple-silicon checkout, a usable desktop session,
Python with `venv`, and an authenticated `gh` CLI that can read public releases.
No administrator access, global install, audio-device changes, or accessibility
permission is needed by the supported control protocol.

From the repository root, run:

```sh
SPIKE="$PWD/native/docs/spikes/soundcraft"
python3 "$SPIKE/prepare.py"
python3 -m venv "$SPIKE/.work/venv"
"$SPIKE/.work/venv/bin/pip" install -r "$SPIKE/evidence/python-requirements.txt"
"$SPIKE/.work/venv/bin/python" "$SPIKE/test_fixtures.py"
"$SPIKE/.work/venv/bin/python" "$SPIKE/check_fixtures.py" \
	"$PWD/native/tests/fixtures/soundcraft"
"$SPIKE/.work/venv/bin/python" "$SPIKE/probe.py" \
	--app "$SPIKE/.work/install/SoundCraft.app/Contents/MacOS/SoundCraft" \
	--cli "$SPIKE/.work/install/soundcraft-cli-0.18.0-macos-universal/soundcraft-cli" \
	--output "$SPIKE/.work/app.json"
python3 "$SPIKE/check_evidence.py"
```

`prepare.py` refuses a different latest release, moved tag, or mismatched
checksum. It checks all downloads before extraction, then checks extracted
binary hashes before executing version and schema queries. A fresh installation
mounts the DMG read-only, copies the app locally, and detaches the image.
An OS launch denial is a blocker. Do not remove quarantine or bypass security
settings to make the result pass.

The fixture tests report four passes. The app probe exits zero only after its
positive and negative assertions pass and all app instances exit normally.
Each run uses a new `probe-*` directory and fresh settings. Failures preserve
the sanitized partial transcript. The script removes only copies of synthetic
sources and sessions that it created for that run.

The output records every `soundcraft-cli app --port <PORT> METHOD JSON` call.
It never uses headless `run`. Command replies, rather than private session JSON,
provide IDs and target inspection. A missing app, display, permission, media,
or dependency must remain a failed or skipped gate.

`check_evidence.py` checks the committed capture, not `.work/app.json`.
After reviewing a fresh capture, copy that capture, `.work/release.json`, and
`.work/commands.json` into `evidence/` and run the check again before publishing.
It checks expected successes, explicit negative controls, normal app exits, and
local-path redaction. `requirements.txt` lists direct dependencies. The frozen
file used above records every Python package from this run.

To regenerate committed fixtures, run:

```sh
python3 "$SPIKE/generate_fixtures.py" "$PWD/native/tests/fixtures/soundcraft"
```

Compare generated bytes and hashes before publishing. The fixture definitions
are in [the fixture reference](../../../tests/fixtures/soundcraft/README.md).

## Repeat the pin before #110

Do not treat this early result as approval for a later release.

1. Fetch the newest release metadata:

   ```sh
   gh api repos/storytold/soundcraft/releases/latest --jq '{tag_name,published_at,target_commitish,assets:[.assets[]|{name,digest}]}'
   ```

2. Resolve the selected tag with `gh api repos/storytold/soundcraft/git/ref/tags/TAG`.
   If it is annotated, resolve the tag object to a full commit.
3. Read `docs/cli.md`, `docs/control-protocol.md`, and the linked import,
   save, MIDI, and sampler sources at that full commit. Check release notes
   for portability, overlap, mapping, and serialization changes.
4. If the release changed, update `pin.json` with the date, tag, full commit,
   artifact hashes, and extracted executable hashes. Update artifact filenames
   in `prepare.py` and the CLI path in the commands above. Preserve the old
   `.work/install` under a different name inside `.work/` before extraction.
   Verify the new downloaded checksums before executing either binary.
5. Capture fresh app and CLI versions and `commands --json`. Compare the
   relevant command IDs, JSON parameters, position units, and error behavior.
   Adjust the probe only for documented changes, not to hide failed semantics.
6. Run the independent fixture tests and the complete real-GUI probe above.
   Recheck same-track overlap, same-pitch import and export, 44.1 kHz conversion,
   mapping, gate, one-shot, octave rate, choke rejection, edits, quit/reopen,
   source-free relocation, and the missing-media negative control.
7. Review every matrix row against fresh evidence. Retain fallback requirements
   unless a new probe proves the replacement.

If the app or required editable workflow is no-go, apply D19: M3 targets #109's
DAW-neutral bundle, checked in another open DAW. This result does not authorize
implementing that bundle or another exporter during #95.

## Complete the manual sound gate

Use copies of the synthetic fixture and session, not a personal project.
After the automated probe, its final relocated copy intentionally lacks the
impulse media for the negative control. Repeat the positive workflow or make
a separate session through the documented import commands for listening.

1. Ask the maintainer to open that synthetic session in the pinned GUI with
   normal audio output. Leave the system default audio device unchanged.
2. Have the maintainer check the two overlapping hits and the edited note.
3. Compare gate and one-shot playback with the short note. Check octave rate,
   baked choke, and retained tails against Brownnote reference renders when
   those renders exist.
4. Record the maintainer's observations separately from automated inspection.
   A screenshot, an offline waveform, or a virtual audio path does not pass
   this listening or real-device gate.
