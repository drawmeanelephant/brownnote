# Studio CodeQL evidence

This review covers CodeQL alerts 1 through 17 in `scripts/studio.py`.
The starting revision is `cb1a73066132c4fd743d20e94e1d4cde732461ff`.
It is not a repository-wide audit.

## HTTP and filesystem boundaries

The existing request gate requires a loopback Host by default. Remote
binding requires `STUDIO_ALLOW_REMOTE=1`, and Host must still be an IP
literal or loopback name. API requests require `X-Studio-Client: 1`.
Present Origin and Referer headers must match Host. There is no CORS
preflight support. These controls protect against browser cross-site
requests, not a local client or an opted-in remote client.

Patch and sample names already excluded path separators, absolute paths,
and traversal components. Their `$`-anchored `match` checks nevertheless
accepted a final newline. Library slugs replaced non-alphanumeric
characters with hyphens. Neither check prevented a valid basename from
resolving through an existing symlink.

The shared `_workspace_path` check rejects paths outside the workspace
and symlinked descendants, including dangling, cyclic, and directory links.
The workspace root itself remains trusted and may have a canonical alias.
Patch and sample names now use `fullmatch`. Atomic writes validate their
destination before creating a temporary file. Intake validates both the
WAV and definition destination before changing either.

Library scans skip symlinked audio and definitions. Promotion checks its
source, definition, and normalized destination. Existing non-symlinked
patches, uploaded samples, library intake, promotion, default selection,
and deletion retain their formats.

These checks cover symlinks present when a request arrives. They do not
claim protection against a separate local process replacing directories
between validation and file access. The server is not a sandbox against
another process running as the same user.

## Process arguments

The alert 17 SARIF traces identify the preset `name` argument, not proof
of shell execution. `_run_group` passes an argv list to `Popen` without a
shell. `presets.sh` consumes its preset or genre as the first positional
argument, shifts it, and checks a finite case statement. Its option loop
consumes each value as `"$2"` with `shift 2`. A quoted phrase is one
argument, even when it contains spaces, shell syntax, or an option name.
Numeric seed, bars, and tempo values are converted to bounded integers.

The new lookup matches the seven FX presets and four song genres in the
script. It does not remove valid custom phrases. The real-script test
exercises HTTP, `_run_group`, the unchanged shell parser, and its child
argv. Only the external synthesizer and encoder are test stand-ins.
That test proves argument boundaries, not the behavior of an installed
kujamba binary or real pedal audio.

No argument-injection exploit was established for the original preset
flow. The finite lookup removes unnecessary request-controlled argument
values and rejects unsupported names before spawning a process.

## Regression evidence

`tests/studio_security.py` uses actual HTTP handlers on a loopback socket
with a disposable workspace. It does not send requests to outside hosts
or access user files. The original implementation returned 200 for
symlinked patch reads, directory-linked sample and library writes, and
newline-suffixed names. The original implementation already passed the
cross-site request, static symlink escape, and real-script phrase tests.

Required checks for this change are `python3 tests/studio_security.py`,
`python3 tests/studio_smoke.py`, `make test`, and `make native-test`.
Swarm runs acquire the shared whole-check lock and reuse the shared Cargo
target with two jobs. Results and any skips are recorded in the PR.

The new CodeQL analysis on the PR or main remains the authority for alert
resolution. This document does not mark all 17 alerts fixed, suppress
queries, or dismiss alerts. Listening, real NINJAM servers, and installed
kujamba argument parsing are not covered by these fixtures.
